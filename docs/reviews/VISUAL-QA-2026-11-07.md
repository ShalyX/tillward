# Tillward visual QA — November 7, 2026

The new landing page and business workspace were reviewed locally, with repairs that keep Tillward's BTC-backed working-capital, invoice and receipt-funded repayment purpose intact. Public deployment was not changed. No wallet requests or transactions were made.

## Findings repaired

| Priority | Location | Finding and repair |
| --- | --- | --- |
| P1 | `src/entry.ts` | The production build attached the landing CSS preload to the conditional dynamic-import expression, including the workspace branch. Workspace JavaScript rendered with landing styles and mobile navigation overflowed to 482 px. Separate explicit import branches now load the matching CSS. Verified against the compiled app, not only Vite development. |
| P2 | `src/main.ts`, `src/workspace.css` | Narrow proportional repayment tiles clipped their financial labels. A separate proportional bar now carries the split, with two readable value tiles beneath it. |
| P2 | `src/main.ts` | The example workspace still illustrated the older fee-free, 100%-allocation model and a 1,500 MUSD reserve. Its illustrative data now uses the current 99% maximum, separate 1% fee, zero operating floor, fee-aware available balance, and a fee activity row. Historical live-account behavior and transaction handlers are preserved. |
| P2 | `src/landing.css`, `src/workspace.css` | Muted secondary labels failed contrast checks. Darkened the affected labels without changing the approved palette. |
| P2 | `src/landing.css`, `src/workspace.css` | Improved narrow-phone header spacing, receipt sizing, checkout amount typography, and control scroll margins. Exact invoice precision remains visible. |
| P2 | `src/main.ts`, `src/workspace.css` | Added a workspace skip link, current-page semantics, navigation tooltips, announced calculator results/errors, and keyboard-focusable scrollable tables with mobile scroll hints. |
| P2 | `index.html`, `src/entry.ts`, `public/loading.css`, `src/landing.ts` | Corrected loading/error landmark semantics and supplied a descriptive role/label for the receipt illustration. |

## Verification

| Check | Result |
| --- | --- |
| Development layout matrix | Landing + Overview, Invoices, Repayment rules, Activity, Manage loan at 320, 390, 650, 768, 1024 and 1440 px: 36 combinations, no document overflow, clipped checked controls, or page exceptions. |
| Production layout matrix | Same 36 combinations passed after the import fix. Additionally checked that workspace navigation receives workspace styles; the loaded sheet is the built `main-*.css`, not `landing-*.css`. |
| Accessibility | axe-core 4.14.0: 16 development view/state scans and 4 built-app scans reported zero violations after repairs. Automatic tools still request manual contrast inspection for illustrated/pseudo-element backgrounds, decorative glyphs and some table/dialog content. This is not a full accessibility certification. |
| Receipt calculation | 500 MUSD at 99% shows 495 MUSD repayment, 4.95 MUSD service fee and 0.05 MUSD retained. Zero allocation and invalid-input states also checked. |
| Keyboard and dialogs | Workspace skip link works; Escape closes the invoice modal; focus returns to its trigger; a focused lower-page control remains above the mobile bottom navigation. |
| Motion | Receipt entrance runs with ordinary motion preferences. Reduced motion disables the receipt animation and exposes revealed content. |
| Loading and errors | Observed the branded workspace loading state and named status. An interrupted deployment-config request renders an actionable Reload state. |
| Controlled account states | Existing local RPC fixture exercised fees, loan risk, failed risk reads, unresolved transactions, stale snapshots and exact-decimal customer checkout. Screenshots use fixture balances, not public transactions. |
